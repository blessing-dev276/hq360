Do# HQ360 — How It Works

HQ360 is the codebase for **hq360.space**, a marketing agency site for an author/publishing-services and growth agency. It's built with TanStack Start + React 19 + Vite, styled with Tailwind v4, backed by Supabase (Postgres), and deployed as a Nitro Cloudflare bundle. Beyond the public marketing site, it includes two internal tools (an author-prospecting engine and an author-visibility audit product) and a token-based NOWPayments invoicing system.

## Stack

- **Framework**: TanStack Start (file-based routes in `src/routes/`), React 19, Vite 8
- **Styling**: Tailwind v4
- **Data**: Supabase (Postgres + Auth + Storage), SQL migrations in `supabase/migrations/`
- **Package manager**: bun (`bun install`, `bun dev`, `bun run build`, `bun run lint`)
- **Deploy target**: Nitro Cloudflare bundle (`.output/`), configurable via `vite.config.ts`

## App shell

`src/routes/__root.tsx` wraps every page in a `QueryClientProvider`, shows a global route-progress bar, and injects the `Organization` JSON-LD (`src/lib/seo.ts`). The marketing chrome (`SiteHeader`, `SiteFooter`, `CookieBanner`, `LeadPopup`, `VoiceMessage`) is hidden on "private" full-bleed surfaces: `/author-audit`, `/admin`, `/scout`, and `/pay/*`.

## What's in it

### 1. Marketing site

Positioning/landing pages for the agency and its verticals:

- General: `about`, `agencies`, `industries` (hub), `team`, `testimonials`, `reviews`, `results`, `resources`, `faqs`, `guarantee`, `contact`, `privacy`, `terms`
- Industry pages: `hvac`, `roofers`, `law-firms`, `med-spas`, `plumbers`, `real-estate`, `home-services`, `local-business`, `ecommerce`, `authors`, `coaches`, `creators`, `book-launch`
- Content/SEO hub: `insights` (index, `$slug`, `answers.$slug`, `guides.$slug`, `glossary`), `blog` (index, `$slug`), `capabilities` (index, `$slug`), `services` (index, `$slug`), `work` (case studies, index, `$slug`)

### 2. Public lead-gen tools (`/tools`)

- `tools/index.tsx` — tool directory
- `tools/author-visibility-audit.tsx` — self-serve version of the Author Visibility Audit
- `tools/website-audit.tsx` — self-serve website audit
- `tools/$tool.tsx` — generic dynamic tool page

### 3. Author Visibility Audit (`src/lib/author-audit/*`)

The agency's flagship deliverable: audits how discoverable an author is online (Amazon, Google, bio consistency, etc.) and produces a report.

- `research.ts` gathers data; `verification-fields.ts` / `quality-check.ts` mark each field verified/unverified/conflicting; `synthesize.ts` turns research into a report + roadmap
- `pdf-report.tsx` / `image-report.tsx` render/export the report
- `client-access.server.ts` / `client-security.ts` gate private client audits behind a token
- Public pages: `/author-audit`, `/author-audit/$author/$book`, `/tools/author-visibility-audit`
- Admin management: `src/routes/api/admin/author-audits.*` (comparables, findings, roadmap, strengths, evidence assets, reader-journey steps, bulk-import, quality-check, publishing, synthesize), UI in `AuthorAuditAdmin.tsx` / `ClientAuditPublishing.tsx`
- Data: `author_visibility_audits`, `author_audit_v2`, `private_client_audits` migrations

### 4. Scout — author prospecting (`src/lib/scout/*`, `/scout`)

Internal lead-sourcing engine for finding prospective author clients.

- Pipeline: **discover** authors/books (Reedsy Discovery, public catalog pages, Google/Amazon search via SerpApi) → **enrich** (automated website research, contact discovery) → **batch** → **export** for outreach
- `db.ts` defines row types for `scout_sources`, `scout_authors`, `scout_books`, `scout_batches`, `scout_prospects`
- `adapters/website-research.ts` does automated research on a prospect's site; `sources/reedsy` and `sources/public-pages` are per-source crawlers with rate-limit/robots tracking
- `csv.ts` / `normalize.ts` / `amazon-url.ts` support data import/normalization
- Admin API: `src/routes/api/admin/scout-*.ts`; UI: `ScoutApp.tsx`
- Data: `scout_prospecting`, `scout_publication_year`, `scout_website_research_enabled`, `scout_batches`, `scout_manual_ingest`, `scout_crawling`, `scout_reedsy_only`, `scout_google_amazon_workflow` migrations

### 5. Payments / invoicing (`src/lib/payments/*`)

Admin-generated, token-based invoicing — not a shopping cart.

- `types.ts` defines the shared `Invoice` shape: `provider: nowpayments | paystack | remita (historical values; NOWPayments is the only active provider)`, `status: draft | pending | paid | refunded`, `currency: USD | NGN`, `amount_minor`, `payment_token`, `environment: demo | live`
- `nowpayments.server.ts` — crypto checkout via NOWPayments (sandbox/live by env var), validates checkout URLs, signs/verifies IPN webhooks
- Paystack and Remita are inactive. Legacy provider labels are retained for historical records; new invoices and checkout use NOWPayments only. The retired Paystack webhook returns HTTP 410.
- `invoices.server.ts` — shared invoice CRUD/issuance logic

**Flow**: admin creates an invoice in `PaymentsAdmin.tsx` → gets a `payment_token` link → buyer opens `/pay/$token` (header/footer suppressed) → `GET/POST /api/pay/$token` fetches/verifies status → the NOWPayments webhook (`/api/payments/nowpayments/ipn`) mark the invoice paid → admin manages invoices via `/api/admin/invoices*`.

Data: `payment_invoices`, `nowpayments`, `invoice_usd`, `nowpayments_only` migrations.

### 6. Admin dashboard (`src/components/admin/*`, `/admin`)

Gated by `AdminGate.tsx` (basic auth via `ADMIN_USERNAME`/`ADMIN_PASSWORD`). Covers:

- `AdminOverview.tsx` — dashboard home
- `AuthorAuditAdmin.tsx` / `ClientAuditPublishing.tsx` — author audits
- `PaymentsAdmin.tsx` — invoices/payments
- `ScoutApp.tsx` — prospecting
- Plus API-backed CRUD for case studies, portfolio, team members, testimonials, and file uploads

### 7. Leads / contact handling

Public endpoints (`src/routes/api/public/`: `inquiry.ts`, `growth-audit.ts`, `newsletter.ts`, `resource-request.ts`, `voice-message.ts`) persist submissions to Supabase, then best-effort:

- **Email** (`src/lib/email.server.ts`) — sends via Resend if `EMAIL_PROVIDER=resend` + `RESEND_API_KEY` are set; otherwise logs and continues (the lead is still saved)
- **Webhook forwarding** (`src/lib/lead-forwarding.server.ts`) — optional, pipes leads to GoHighLevel/HubSpot/Zapier/Make via `LEAD_WEBHOOK_URL`
- **Mailto fallback** (`src/lib/lead-mailto.ts`) — client-side, opens a pre-filled Gmail compose tab so a copy reaches the inbox even with no email provider configured

### 8. SEO & analytics

- `src/lib/seo.ts` — `buildSeo()`, canonical URLs, OG/Twitter tags, `organizationSchema()` JSON-LD
- `sitemap.ts` — backs `/sitemap.xml`
- `page-heads.ts`, `google-analytics.ts`, `clarity.ts` — GA and Microsoft Clarity wiring

## Data model (Supabase, chronological)

1. Initial/base schema
2. `growth_inquiries` — contact/audit leads
3. `portfolio`
4. `team_members` (+ `team_members_blurb`)
5. `case_studies`
6. `testimonials` (+ `testimonials_video`)
7. `author_visibility_audits` → `author_audit_v2` → `private_client_audits`
8. `scout_prospecting` → `scout_publication_year` → `scout_website_research_enabled` → `scout_batches` → `scout_manual_ingest` → `scout_crawling` → `scout_reedsy_only` → `scout_google_amazon_workflow`
9. `payment_invoices` → `nowpayments` → `invoice_usd` → `nowpayments_only`

## Integrations (`.env.example`)

- **Supabase** — URL, project ID, publishable + service-role keys (plus `VITE_` copies for the client bundle)
- **Resend** — transactional email (optional)
- **Lead webhook** — generic forwarder to GoHighLevel/HubSpot/Zapier/Make (optional)
- **Admin auth** — `ADMIN_USERNAME` / `ADMIN_PASSWORD`
- **ElevenLabs** — speech-to-text for the voice-message feature
- **Google Books API** — public catalog lookups
- **SerpApi** — structured Amazon search for Scout
- **NOWPayments** — crypto checkout (sandbox/live)

Note: no Anthropic/Claude API key is configured in `.env.example`, despite `@anthropic-ai/sdk` being a dependency.
