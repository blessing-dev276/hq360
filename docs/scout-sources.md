# Scout public-source collection

## Run and deploy

1. Apply `supabase/migrations/20260921090000_scout_crawling.sql` after the existing Scout migrations, using the project's normal migration process. The migration adds tables, columns, service-role-only functions, and removes the unsafe unique constraint on author names. Existing identities remain unverified; previously conflated identities need staff review.
2. Configure the existing server Supabase credentials. Optionally set `GOOGLE_BOOKS_API_KEY`; public Google API quota may require a project key. Set `SCOUT_CONTACT_EMAIL` to the operator's public contact address.
3. Set a long random `CRON_SECRET` in the host environment. `vercel.json` invokes `/api/cron/scout` daily at 06:00 UTC. The repository currently builds with Nitro's Vercel preset; this change preserves that preset. Vercel sends the secret in the authorization header ([official documentation](https://vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs)). An external scheduler may call the same GET endpoint with `Authorization: Bearer <secret>`; `SCOUT_CRON_SECRET` is a fallback when `CRON_SECRET` is unset. No secret means the endpoint refuses all requests.
4. Open Scout → Sources. Save a query or genre, set page/record limits, and select Manual, Daily, or Weekly. Use Run crawl for a manual run. Sources start with manual schedules; deploying does not silently enable harvesting.
5. Review source history, raw source URLs, and the identity review queue. Verify identities with evidence, reject incorrect records, or merge explicitly into another author ID. A merge resets the survivor's verification so its combined identity must be checked.

Each scheduler invocation processes one due source. The default daily tick covers Google Books, currently the only scheduled source. If more scheduled sources are onboarded, increase tick frequency for the host plan or invoke the endpoint repeatedly, with bounded requests. Use a host request duration of at least 120 seconds for individual crawls; a multi-source manual discovery request can take longer. Partial saves survive host termination and leases expire after five minutes.

## Architecture

- `adapters/types.ts`: common `SourceAdapter.discover()` and optional `countAvailable()` contract. The runner injects a mandatory-in-practice `fetchJson`; adapter modules never call network APIs themselves. Errors throw, whereas an empty result means no results.
- `adapters/google-books.ts` and `adapters/open-library.ts`: independent discovery, parsing, and pagination. Raw source metadata is preserved.
- `transport.server.ts`: approved HTTPS hosts only; rejects credentials, nonstandard ports and redirects. Before every request or cache use, checks source enablement/access and the active lease. Robots must be available (404 means absent); unavailable/challenged robots fails closed. Honors allow/disallow, agent groups, wildcards, crawl-delay and X-Robots-Tag noindex. Requests are spaced by at least the configured interval plus up to 500 ms jitter. Three bounded attempts for 429/5xx, exponential backoff, and Retry-After; a long cooldown stops the run rather than shortening the server's requested delay. 401/403/redirects/challenge responses stop collection. Responses are limited to 2 MB.
- `sources/public-pages/parse.ts`: pure future-adapter helpers for JSON-LD Book/Person graphs, semantic item properties, Open Graph, canonical URLs and same-origin public anchors. Invalid JSON-LD blocks do not discard other valid data. Missing author/title produces no record. It honors noindex/nofollow and does not invent pagination, titles or author identities. This is parsing infrastructure, not an enabled generic crawler.
- `normalize.ts`: normalized book fields and URL/date handling; identity evidence scoring; fuzzy-title review hints; qualification signals. Missing values stay unknown. Source ratings retain their platform. Publication month/year is never turned into an invented day.
- `crawler.server.ts`: shared SCRAPE → NORMALIZE → DEDUPLICATE → IDENTITY REVIEW → QUALIFICATION path used by admin discovery, source runs, and cron. Optional enrichment stays manual until a permitted adapter exists. Cross-source matches always await review. Counting on each search keystroke was removed to avoid uncontrolled requests.
- SQL functions: durable global lease, transactional save, record quotas, identity review, and audited manual merges. A single global crawler lease serializes domains across workers; this favors low-volume safety over throughput. Each run has a 90-second working budget. Source runs fail independently.

## Persistence and identity

Existing `scout_authors`, `scout_discovered_books`, and `scout_review_counts` remain the normalized entities. New fields include source/profile URLs, subtitle, categories, cover, confidence, identity status, verification time, social URLs, and qualification. `scout_book_sources` stores every collected source URL and its normalized observation; `scout_batch_books` preserves repeat discoveries across batches. `scout_crawl_runs` stores timestamps, totals and URL-specific errors. `scout_page_cache` stores API responses for 24 hours and robots for one hour, without API keys in cache keys. `scout_identity_reviews` records possible matches and manual evidence. All new tables have RLS enabled and no anonymous/authenticated grants.

Exact source URL and same-source profile ID are safe anchors for idempotent storage. Title matching is scoped to an already identified author. ISBN, normalized name, official website, book overlap, publisher, bio, social links and public location provide review evidence; fuzzy titles are suggestions only. Name-only evidence scores 10, never merges. Stronger matches can reach 90–100, but an algorithm does not confer verified identity. Same-name Google Books authors without stable author profiles can remain separate until review; this is intentional. A manual merge preserves source observations, review counts, old duplicate book/prospect history and suppression flags; merged records remain audit records and cannot become outreach identities.

Lead qualification stores website/email presence, Goodreads presence, multiple-book and recent-release signals, per-source review counts, unknown series/publisher/independence values, visibility notes and a priority score. Only a human can establish identity verification. The database refuses transitions to qualified/contacted for unverified or merged authors and respects existing do-not-contact suppression. The system does not send outreach.

## Adding a source

1. Inspect current public HTML/navigation, robots, terms and behavior. Record reviewed URLs/date, permissible use, identity evidence, rate limits and access status in a migration. Use `manual_only`, `blocked` or `unknown` if automated access is not established. Do not toggle an unsupported source into permission.
2. Add a domain-specific module under `sources/<source>/` or `adapters/`. Implement `SourceAdapter`, return `DiscoveredBookCandidate[]` and throw on failed access. Require original public source URLs. Prefer structured data and native API metadata. A parser fixture must be based on observed permitted content; do not assume Reedsy selectors from old markup.
3. Register the adapter in `SOURCE_ADAPTERS` and its fixed approved hosts in `SOURCE_HOSTS`. The current transport intentionally accepts JSON only. A future HTML transport must preserve the same lease, host, robots, rate, size and redirect controls, plus page-level noindex/nofollow. Do not pass arbitrary admin URLs to fetch. A browser renderer needs the same controls on every navigation/subresource and is not currently installed.
4. Add the registry row through a migration with conservative limits. Scheduling must reflect the source's actual policy. Update the source dashboard only if the source requires genuinely new controls.
5. Add parser, pagination, blocked-access, missing-field, provenance and homonym fixtures. Run `bun test tests/scout*.test.ts`, `bunx tsc --noEmit`, `bun run build`, and lint.
6. Reassess source terms/robots periodically. Blocked sources cannot be unblocked by the ordinary dashboard; restoring access requires an operator to document the new evidence and update the registry. A retry is not permission to bypass a restriction.

## Operational limits

No remote migration or deployment is performed by adding these files. Test the migration against a staging database before rollout. SQL tests use PGlite PostgreSQL, including the real migration and privileged functions; transport tests use controlled HTTP fixtures. Cached pages expire logically but should be periodically pruned (`DELETE FROM scout_page_cache WHERE expires_at < now()`). Old interrupted crawl rows can be recognized by their running status and expired source lease; a subsequent claim marks them failed. Keep source logs and evidence according to the organization's retention policy.
